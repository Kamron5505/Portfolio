# Портфолио — Kamron Fazilov

Персональный сайт **Камрона Фазилова**, frontend-разработчика из Ташкента.
Три языка: EN (`/`) · UZ (`/uz`) · RU (`/ru`).

**Стек:** Next.js 15 (App Router) · React 19 · TypeScript · Tailwind CSS ·
Neon Postgres · Vercel Blob · Serwist (PWA).

Публичные страницы статические. Контент лежит в базе и правится через админку;
после сохранения затронутые страницы перегенерируются автоматически.

## Быстрый старт

```bash
npm install
cp .env.example .env.local   # заполните значения
npm run db:setup             # создаст таблицы и перенесёт контент в базу
npm run dev
```

Сайт — <http://localhost:3000>, админка — <http://localhost:3000/admin>.

### Без базы данных

Сайт запустится и без `DATABASE_URL`: контент возьмётся из `src/lib/data.ts` и
`src/lib/i18n.ts` — это значения по умолчанию. Не будет работать только админка.

## Админка

`/admin`, вход по логину и паролю. Разделы:

| Раздел | Что меняет |
| --- | --- |
| Профиль | Имя, роль, email, домен, фото, резюме (PDF) |
| Проекты | Публикация, обложки, теги, описания на 3 языках |
| Хайлайты | Фото и короткие видео (файл или ссылка), подписи на 3 языках |
| Услуги | Блок «Что я делаю» |
| Навыки | Группы технологий |
| Соцсети | Ссылки и иконки (идут и в `sameAs` для schema.org) |
| Тексты сайта | Все надписи, заголовки секций и SEO-описания |

Пароль хранится только как хеш bcrypt. Сессия — подписанный JWT в httpOnly-cookie
на 12 часов. `/admin` закрыт middleware, а каждое действие записи дополнительно
проверяет сессию само.

### Переменные окружения

Все описаны в `.env.example`. Обязательные: `DATABASE_URL`,
`ADMIN_SESSION_SECRET`, а для первичной настройки — `ADMIN_USERNAME` и
`ADMIN_PASSWORD`.

`BLOB_READ_WRITE_TOKEN` нужен на Vercel: там файловая система доступна только на
чтение, поэтому загрузки идут в Vercel Blob. Локально без токена файлы пишутся в
`public/uploads`.

### Смена пароля

Поменяйте `ADMIN_PASSWORD` в `.env.local` и снова выполните `npm run db:setup` —
скрипт идемпотентен, контент он не тронет, а хеш пароля обновит.

## Живой чат

Плавающая кнопка в правом нижнем углу на всех публичных страницах. Канал
общий: посетители видят сообщения друг друга, а администратор отвечает из того
же виджета — сервер узнаёт его по cookie админки и метит сообщения меткой
«Админ». Транспорт — опрос `/api/chat` раз в несколько секунд (на serverless
WebSocket не живёт); в фоновой вкладке опрос не идёт.

Чат работает и **без базы данных**. Хранилище выбирается автоматически
(`src/lib/chat-store.ts`):

| Условие | Хранилище | Что это значит |
| --- | --- | --- |
| Задан `DATABASE_URL` или `LOCAL_DB=1` | Таблицы `chat_messages` / `chat_presence` | История переживает перезапуск и общая для всех инстансов |
| Не задано ничего | Память процесса | История теряется при перезапуске сервера |

Режим «в памяти» рассчитан на один процесс (`next dev`, `next start` на своём
сервере). На Vercel инстансов функции несколько и они эфемерные — там у разных
посетителей история может разойтись, поэтому для настоящего чата на проде
нужен `DATABASE_URL`.

Кнопка видна всегда. Если сервер не отвечает, виджет показывает
«Подключение…» и продолжает попытки — исчезнуть он не может.

> Чат по `http` на IP в локальной сети (`http://192.168.x.x:3000` с телефона)
> работает: идентификатор клиента генерируется без `crypto.randomUUID()`,
> которого вне secure context не существует.

## PWA

Сайт устанавливается на телефон и компьютер: манифест (`src/app/manifest.ts`) и
service worker (`src/app/sw.ts`, собирается в `public/sw.js`).

Офлайн: страницы и статика кешируются, при потере сети показывается `/offline`.
Админка и `/api` не кешируются никогда — закешированная форма означала бы потерю
данных. В `next dev` service worker отключён, чтобы не прятать свежие правки.
